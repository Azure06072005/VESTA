#### Finding 1: Foreign Flow `buy_value` / `sell_value` Mismatch (`F051`) — **CONFIRMED BUG**
- **Query Results on `core.market_foreign_flow_daily`**:
  ```sql
  SELECT count(*) total_rows, 
         count(*) FILTER (WHERE buy_value > 0) has_buy_val,
         count(*) FILTER (WHERE sell_value > 0) has_sell_val
  FROM core.market_foreign_flow_daily;
  ```
  - `total_rows`: **4,838,812**
  - `has_buy_val`: **215,112** (~4.4%)
  - `has_sell_val`: **< 5%**
- **Root Cause in `src/crawlers/cafef_foreign_flow.py`**:
  Lines 86–89 map AmiBroker CSV columns directly:
  ```python
  df["buy_volume"] = pd.to_numeric(df["open"], errors="coerce").fillna(0)
  df["sell_volume"] = pd.to_numeric(df["high"], errors="coerce").fillna(0)
  df["buy_value"] = pd.to_numeric(df["low"], errors="coerce").fillna(0)
  df["sell_value"] = pd.to_numeric(df["close"], errors="coerce").fillna(0)
  ```
  Inspecting the actual raw CafeF feed (`CafeF.NN_HSX.04.09.2026.csv`):
  ```text
  <Ticker>,<DTYYYYMMDD>,<Open>,<High>,<Low>,<Close>,<Volume>,<OI>
  AAA,20260904,0,1072600,0,0,0,0
  AAN,20260904,0,295500,0,0,0,0
  ```
  In CafeF's AmiBroker export for foreign trading (`NN`), `<Low>` and `<Close>` are **NOT trading values** in VND — they are almost uniformly `0.0`. CafeF only exported foreign volumes in this file. The value columns were mapped under a false assumption about AmiBroker column semantics.

#### Finding 2: Fundamentals Source Collision (`F052`) — **CONFIRMED SEVERE SCHEMA & PAYLOAD BREAK**
- **Table Schema Check**:
  `core.fundamentals` primary key is `(symbol, report_type, period_end, fetched_at)`.
  **There is NO `source` column.**
- **Vintage Inspection for `FPT` (`income_statement`, `2026-06-30`)**:
  Two distinct rows exist in production right now:
  1. Vintage 1 (`fetched_at = 2026-08-28`, from `vnstock_data`):
     - JSON keys are standardized uppercase English financial codes:
       `['IS_REVENUE', 'IS_REVENUE_DEDUCTIONS', 'IS_NET_REVENUE', 'IS_GROSS_PROFIT', ...]`
  2. Vintage 2 (`fetched_at = 2026-09-06`, from `cafef_finance_enhancer.py`):
     - JSON keys are raw Vietnamese line-item strings:
       `['1. Doanh thu bán hàng và cung cấp dịch vụ', '2. Các khoản giảm trừ doanh thu', '3. Doanh thu thuần...', ...]`
- **Impact**:
  Because `get_as_of()` selects the latest `fetched_at`, calling it today will silently return CafeF's Vietnamese string payload. Any downstream feature engineering or pipeline step expecting `row['data_json']['IS_NET_REVENUE']` will immediately raise a `KeyError`.
  Furthermore, `balance_sheet` rows only exist from CafeF, meaning the 4 financial statement types now have mutually incompatible JSON schemas.
